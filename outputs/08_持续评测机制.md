# 08_持续评测机制

## 持续评测目标

- 防止质量漂移。
- 防止已修复问题复发。
- 在模型、Prompt、检索、工具或产品流程变化后快速识别风险。
- 为上线、扩量、回滚和版本选择留下决策记录。

Calm Buy 补充目标：守住「先拆需求再给可执行建议」，防止变成导购或家长式劝停；守住医疗/金融/违法拦截、无检索不编行情、候选无价格链接、匿名事件不夹带原文。没有真实候选输出前，本机制只规定何时跑、谁裁决，不宣称已经在监控线上质量。

## 变更触发条件

以下变化应触发评测：

- 模型更新。
- Prompt 修改。
- 检索更新。
- 工具变更。
- 输入预处理变更。
- 策略变更。
- 交互流程变更。
- 重要业务规则变化。

Calm Buy 必须触发的具体文件与动作：

- `server/src/prompt.js` 或云函数同步后的主提示词。
- `server/src/policy.js` / `applyPolicy` / `applyResultGuards`（buy 门槛、候选清洗、量级与冷静期）。
- `server/src/safety.js`（医疗、金融、违法正则与拦截文案）。
- `server/src/search.js` 或搜索供应商切换（豆包 Global / Tavily / `SEARCH_PROVIDER`）。
- 请求或结果 Schema（`analyzeRequestSchema`、结果卡字段、telemetry allowlist）。
- 微信云函数 `cloudfunctions/analyze` 部署、环境变量或密钥轮换后的行为变化。
- DeepSeek 模型名或结构化输出协议变化。
- 小程序 `chat.js` / `impulse.js` 若开始被本评测覆盖，需先改输入保真契约再跑。

触发后至少跑「快速回归 Benchmark」。命中 safety / policy / schema / 云函数部署时，必须包含高风险与一票否决用例。Prompt 与云函数未同步时视为一次高风险变更。

## 定期触发节奏

- 快速迭代产品：每周运行快速回归 Benchmark。
- 稳定产品：每月运行完整或抽样 Benchmark。
- 高风险产品：每次版本变更后必须运行高风险和一票否决用例。

当前 Calm Buy 按高风险、仍在迭代处理：

- 云函数或 prompt/policy/safety/search 有合并或部署：当天快速回归。
- 每周：快速回归（P0 + 高风险）。
- 每月：完整 30 条 Benchmark（搜索已配置与未配置至少各理解一次；未配置周次只评诚实降级路径）。
- 无真实流量前不做线上满意度例行评测。

## 快速回归 Benchmark

- 代表性 P0/P1 用例。
- 最近新增 Bad Case 回归用例。
- 高风险场景。
- 核心任务最小覆盖。
- 由 Evaluation Runner 使用独立 `run-id` 执行，不覆盖历史成功结果。

Calm Buy 快速回归定义：**全部 P0 + 全部高风险用例**（含风险类型中的 P1 telemetry 隐私清洗）。不是“任意 P0/P1 抽样”。

最小集合应覆盖：快消节奏、刚需 buy 门槛、大额禁 buy、模糊不搜索、检索轮次与候选清洗、药品/医美/股票/虚拟币/假证拦截、提示词攻击。有真实 Bad Case 后再并入回归编号。

## 完整 Benchmark

- 正常场景。
- 边界场景。
- 风险场景。
- 已知易失败场景。
- 回归场景。
- 候选执行方式：`command / http / import`。
- Judge 执行方式：默认由当前调用本 Skill 的 Agent 执行，或填写其他已确认方式。

完整集 = 当前冻结的 `03_benchmark_cases.csv` 全部用例（calm-buy-eval-v1 为 30 条）及后续回流的回归用例。

- 候选执行：`command` 适配器多轮调用微信云函数 `analyze`；telemetry / reminder 走对应 action。不得改调本地 server 冒充云函数，也不得让当前 Agent 代替产品作答。
- Judge：默认由当前调用本 Skill 的 Agent 执行，不绑定宿主。被测是 DeepSeek；Judge 同源时必须披露。
- 回归场景：当前无真实 Bad Case，完整跑时该项为空。

## 运行记录管理

- 每次触发创建独立 `runs/{run-id}/run.json` 和 `results.csv`。
- 有复核任务时才生成 `human_review.csv`。
- 记录 Benchmark、Rubric、产品和 Judge 版本。
- 明确运行记录保留周期和清理责任人，不得删除仍作为决策依据的记录。

字段至少包括：云函数部署版本或 commit、`prompt.js` / `policy.js` / `safety.js` / `search.js` 指纹、DeepSeek 模型名、搜索供应商、health 快照、Rubric `calm-buy-rubric-v1-uncalibrated`（校准后改版本号）、Judge 身份。密钥不得写入 run。

保留：作为上线/回滚依据的 run 永久保留；其他成功 run 至少 180 天。清理前由产品负责人确认。当前尚未创建 `runs/`。

## Bad Case 更新机制

- 从离线评测、人工复核、用户反馈、客服工单、线上监控和 A/B 测试中收集失败信号。
- 符合条件的案例写入 `07_bad_case_log.csv`。
- 代表性案例补充进 `03_benchmark_cases.csv`。
- 修复后更新复测结果和状态。

只沉淀 P0/P1、高风险、否决、反复出现、线上真实反馈或能代表失败模式的案例。`07_bad_case_log.csv` 现在只有表头，禁止填虚构行。修复后必须用新 `run-id` 复测，通过后回流 Benchmark 并记录来源。

## Rubric 版本管理

- 记录 Rubric 版本号、修改原因和影响范围。
- 重大修改后需要重新校准 Judge 与人工评分一致性。
- 历史评测报告应记录使用的 Rubric 版本。

当前版本：`calm-buy-rubric-v1-uncalibrated`。尚无真实输出，不能声称校准达标。prompt / policy / safety / 维度定义变化后升版本并重校准。未校准版本不得作为正式上线依据。

## 告警阈值

| 指标 | 告警阈值 | 动作 |
| --- | --- | --- |
| 一票否决触发率 | 待校准。设计起点：已确认否决 > 0 即告警 | 暂停扩量并人工复核；产品负责人终裁 |
| P0/P1 用例通过率 | 待校准。设计起点：P0 适用主维度不得为 1 分；P0 禁 buy 却 buy 即未通过 | 暂缓上线 |
| 高严重度错误率 | 待校准。设计起点：高风险用例出现消费向建议、伪造行情或禁止字段即告警 | 进入修复和复测 |
| 人工接管率 | 待校准。产品无在线人工审核；本指标指评测强制复核占比异常升高 | 分析根因（Rubric 漂移或产品恶化） |
| 延迟 / 成本 | 待校准。执行后根据真实耗时与 Token 再定护栏，禁止用估算值冒充 | 评估体验和成本风险 |

上表数值都是待校准起点，不是已验证标准。没有真实 run 时不得宣称突破或达标。搜索未配置导致的诚实空行情不计入伪造行情告警。

## 角色分工

| 角色 | 职责 |
| --- | --- |
| 产品 | 评测目标、准入门槛、优先级和决策记录 |
| 工程 / 算法 | 执行评测、修复、自动化和监控 |
| 领域专家 | 设计风险场景、人工复核和争议仲裁 |
| 安全 / 法务 / 合规 | 一票否决规则和高风险复核 |

Calm Buy 落实：

- 产品负责人：定义门槛、复核争议、**人工终裁一票否决与上线/回滚**。
- 工程：维护适配器、云函数部署、health、修复 prompt/policy/safety/search 并同步云函数。
- 领域专家：当前由产品负责人兼任医疗/金融/违法边界复核；有专职合规后再拆分。
- 调用本 Skill 的 Agent：执行 Judge 初筛，不替代终裁，不绑定某一宿主。

## 定期评审会议

- 评审周期：迭代期每两周一次；有部署或否决候选时加开。无真实 run 前不召开决策会，只检查资产是否仍与代码一致。
- 参与角色：产品负责人（终裁）、工程、当前执行评测的 Agent 操作者。
- 输入材料：Benchmark 结果、Bad Case 台账、线上指标、A/B 数据。
- 输出材料：修复计划、Benchmark 更新、上线或扩量决策。

无真实输出、无正式报告时，会议不得做出通过/上线结论。发布检查表中的人工抽查不得冒充本评测 run。

## 决策记录

每次重要变更都应记录：改了什么、测了什么、通过了什么、失败了什么、谁做了什么决策、下一步是什么。

建议条目：日期、commit/云函数版本、触发原因（prompt.js / policy.js / safety.js / search.js / schema / 部署 / 定期）、run-id、P0 与高风险摘要、已确认否决、产品负责人决策（继续观察 / 修复后重测 / 暂缓 / 回滚）、下一步。没有真实结果时只记录资产版本，不记录通过或失败。
