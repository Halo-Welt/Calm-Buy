# Calm Buy UI 设计规范

> 版本：v1.0  
> 适用范围：微信小程序  
> 设计目标：鲜明但克制；先保证阅读和决策效率，再使用运动图形语言。

## 1. 核心原则

1. **一屏只讲一件事**：首页负责开始分析，对话页负责回答当前问题，结果页负责展示判决。
2. **判决优先**：结果页视觉顺序固定为“判决 → 真实需求 → 需求清晰度 / 信息可信度 / 建议强度 → 依据 → 下一步”。
3. **信息必须有任务**：不能帮助理解、判断或操作的文字应删除。
4. **装饰不参与阅读**：英文、编号、图形只能作为少量品牌识别，不得与正文争夺注意力。
5. **统一胜过丰富**：全产品只使用一个字体族、一套字号、一套间距和一套控件尺寸。

## 2. 设计令牌

### 2.1 色彩

| 名称 | 值 | 用途 |
|---|---|---|
| Paper | `#F5F1E8` | 页面背景 |
| Surface | `#FFFDF8` | 卡片、输入框背景 |
| Ink | `#101619` | 正文、描边 |
| Action Blue | `#1648D8` | 主按钮、进度、主要判决 |
| Signal Lime | `#DDFF32` | 需求确认、重要提示 |
| Warning Red | `#FF543C` | 劝停、删除、风险 |
| Caution Yellow | `#FFE53B` | 评测提醒、待验证 |
| Muted | `#5E605A` | 次级正文 |

规则：

- 单个页面最多同时出现 3 个强调色。
- 正文始终使用 Ink 或 Muted，不使用低对比浅灰。
- 颜色不能单独表达状态，必须同时配文字。
- 禁止紫色 AI 渐变、电商红金、玻璃拟态。

### 2.2 字体

全产品统一使用系统无衬线字体：

```css
-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", sans-serif
```

中文统一使用系统无衬线字体。唯一例外是纯数字倒计时，可使用 `"Arial Black", Arial, sans-serif` 作为数字展示字体；该字体不得承载中文或正文。

Display 层必须有明显的海报冲击力：

- 使用系统字体最高可用字重，并允许浏览器合成粗体。
- Display 增加 `3–6rpx` 同色文字描边，并用同色阴影兼容不支持描边的设备。
- 倾斜效果使用 `skewX()`，不使用 `font-style: italic`，避免中文字体回退到较细字重。
- 只对首页主标题、判决、页面标题和计时器使用描边，正文禁止描边。
- Display 与正文的区别来自字重、尺寸和描边，不通过混用字体实现。

| 层级 | 字号 | 行高 | 字重 | 用途 |
|---|---:|---:|---:|---|
| Display | 144rpx | 0.82–0.9 | 900 | 首页主标题、核心判决 |
| H1 | 72rpx | 1.0 | 900 | 页面标题 |
| H2 | 40rpx | 1.2 | 800 | 需求句、关键结论 |
| Body | 30rpx | 1.6 | 600 | 主要正文 |
| Secondary | 26rpx | 1.55 | 600 | 理由、辅助说明 |
| Caption | 24rpx | 1.4 | 700 | 标签、进度、来源 |

规则：

- 最小字号为 24rpx。
- 中文正文不使用全大写、过宽字距或强制斜体。
- 只有 Display/H1 和计时器可以使用几何倾斜。
- 数字计时器必须启用 `font-variant-numeric: tabular-nums`。
- 标题最多 2 行，正文段落尽量不超过 3 行。

### 2.3 间距

采用 16rpx 基础网格。

| Token | 值 | 用途 |
|---|---:|---|
| XS | 8rpx | 图标与文字 |
| S | 16rpx | 紧密元素 |
| M | 32rpx | 控件内部、同组元素 |
| L | 48rpx | 卡片内部 |
| XL | 64rpx | 模块之间 |
| XXL | 96rpx | 页面区块 |
| 3XL | 128rpx | 页面首尾 |

禁止使用不属于上述系统的临时间距，视觉微调除外。

### 2.4 圆角与描边

| 对象 | 值 |
|---|---:|
| 输入框/按钮 | 24rpx |
| 卡片 | 28rpx |
| 胶囊标签 | 999rpx |
| 主描边 | 4rpx |
| 强调描边 | 6rpx |
| 偏移阴影 | 8rpx |

同一组件的圆角不得因页面不同而变化。

## 3. 控件规范

### 3.1 输入框

- 单行输入框：104rpx。
- 对话回答框：最小高度 144rpx；长文本输入框：最小高度 224rpx。
- 左右内边距：32rpx。
- 字号使用 Body。
- placeholder 必须给例子并以省略号 `…` 结束。
- 标签必须常驻，不能只依赖 placeholder。
- 聚焦态增加蓝色外环，不改变布局尺寸。

### 3.2 按钮

- 主按钮：104rpx。
- 次按钮：96rpx。
- 最小触控面积：88×88rpx。
- 每屏最多 1 个主按钮。
- 按钮必须使用明确动作，如“提交回答”“生成判决”“跳过评测”，避免“继续”“确定”。
- 禁用态仍需可读，不只降低到低对比灰色。

### 3.3 卡片

- 卡片内边距统一为 L。
- 同组卡片间距使用 M。
- 一张卡片只承载一个主题。
- 首页卡片最多 3 张；结果页按固定信息顺序排列。

## 4. 页面规范

### 4.1 首页

保留：

- 品牌名
- “先别买”
- 冷静倒计时
- 冲动温度
- 商品输入
- 主按钮
- 原生底部导航

删除：

- 版本号
- 无含义编号
- 英文口号堆叠
- 重复解释“Calm Buy 是什么”的小字

### 4.2 对话页

- 顶部只显示商品名和进度。
- 一次只显示一个问题的可操作区域。
- 用户与系统消息使用固定两种卡片样式。
- 选项按钮高度一致，长文自动换行。
- 输入框和按钮不能随问题类型改变高度。

### 4.3 结果页

- 第一屏必须看到判决、真实需求和置信度。
- 置信信息拆为“需求清晰度 / 信息可信度 / 建议强度”，不得只显示一个模糊总分。
- 理由最多 3 条，每条只表达一个因果。
- 无评测时不渲染空评测卡。
- 无替代时不渲染替代模块。
- 来源标注职责与检索时间；候选不提供价格、购买按钮或购买链接。
- 不转载来源不明的搜索图片。
- 主动作是“放进冷静清单”，其余降为次按钮。

### 4.4 冷静清单

- 每条记录显示商品、判决、状态和日期。
- 到期记录显示“开始复盘”；48 小时复盘使用 4 个点击题，7/30 天只在用户主动回来时出现。
- 状态操作保持 2 个，删除为弱化危险操作。
- 删除需要二次确认或提供撤销。

### 4.5 我的

- 只保留“需求、证据、克制”3 条原则。
- 隐私说明不超过 2 句。
- 匿名改进开关和“删除匿名改进数据”属于必要隐私控制，不受上述两句限制。
- 不重复首页已经表达的宣传文案。
- “产品原则”作为“我的”页面中的子项，不单独占用底部导航。

## 5. 文案规则

1. 标题不超过 14 个汉字。
2. 按钮不超过 8 个汉字。
3. 正文单句优先不超过 28 个汉字。
4. 删除不能改变用户决策的英文、编号、版本号和口号。
5. 同一意思只出现一次。
6. 使用“你”和主动语态，不使用说教或诊断语气。
7. 省略号统一使用 `…`。

## 6. 适配与无障碍

- 页面左右安全边距为 28–32rpx。
- 所有交互元素有明确的按下态。
- 底部导航固定为“首页 / 记录 / 我的”。
- 文本与背景对比度达到 WCAG AA。
- iPhone 底部操作区预留 `env(safe-area-inset-bottom)`。
